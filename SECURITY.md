# Security Policy

## Supported versions

Security fixes target the latest 1.x release. Older revisions may be assessed,
but no support commitment is implied until a maintained-version table is
published with release evidence.

## Report a vulnerability privately

Use GitHub private vulnerability reporting for this repository: open the
repository's **Security** tab, choose **Security Advisories**, and select
**Report a vulnerability**. Do not disclose a suspected vulnerability in a
public issue, discussion, pull request, or test fixture.

Include affected versions, impact, a minimal synthetic reproduction, and any
suggested mitigation. Remove credentials, real client data, bank details,
private documents, and course material before submitting. If private
vulnerability reporting is unavailable, do not create a public report; use the
repository owner's GitHub profile to request a private reporting path without
including vulnerability details.

Maintainers will validate the report, coordinate a fix and advisory when
appropriate, and credit reporters who request attribution. Response and
disclosure timing depends on severity and available maintainers; this document
does not promise an SLA.

## Security boundary

The current public core is synthetic-only and not production-ready. It has no
authority to post, approve, send, pay, file, delete, change settings or bank
details, or process real client data. Report any path that appears to bypass
those boundaries as a vulnerability.
